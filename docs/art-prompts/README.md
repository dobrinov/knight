# Knight Engine pixel-art prompts

One prompt per asset. Each file is self-contained: open it, copy everything under the `---` line
into the image AI, attach the reference images it asks for, and save the result with the exact
file name it gives.

The prompts are generated by `scripts/art_prompts.py`. Edit that script, not the files, and
re-run `python3 scripts/art_prompts.py`. It keeps the shared style block identical everywhere.

The first complete set (all 144 sheets) now lives in `crates/knight-assets/assets/`. It is
bundled and loaded by the `knight-assets` crate and shown in the sandbox's Asset Pack demo.

## What keeps the style consistent

Every prompt carries the same art direction:
- a **fixed 48-colour master palette**, with no other colours allowed;
- **16 art pixels per world unit** (a hex is 28 × 32 px, a unit is 24–28 px tall);
- a **1-pixel `#1B1420` outline** on every sprite;
- **light from the upper left**;
- **3/4 view**, sprites **facing right**, feet on the **bottom row** of each cell;
- fully opaque or fully transparent pixels only;
- **team colour** painted in 4 magenta shades, which the engine recolours per player.

Reference images chain the style from one asset to the next (see the workflow).

## Workflow (do it in this order)

1. **`00-style-reference.md`** → `style_reference.png`. Iterate until you love it, then send it
   to me before going further. Every other prompt attaches it.
2. **Terrain:** `terrain/terrain_grass.md` first, then send it to me. Once approved, it is the
   second reference for all the other terrain prompts. Do `terrain_water.md` early (it's
   animated).
3. **Props:** `terrain/props_trees_oak.md` first (the reference for the other props), then the
   rest, then `terrain/fx_fire.md`.
4. **Units:** `units/unit_human_footman.md` first; once approved it is the reference for every
   unit and monster. Then one faction at a time.
5. **Heroes:** each hero uses its faction's approved basic unit as a reference (footman, grunt,
   sentinel).
6. **Structures:** `structures/building_human_house.md` first (the reference for all
   buildings), then one faction at a time.

Send each asset to me as it's done. I'll check the grid, palette and baseline, remove the
`#00FF00` background if needed, downscale ×N images to native size and wire them into the
engine.

## What each file produces

| Folder | Files | Native size (cells) | Contents |
| --- | --- | --- | --- |
| `.` | `style_reference.png` | 256 × 128 | the style bible |
| `terrain/` | `terrain_*.png` × 19 | 128 × 48 (32² tiles + 32×16 cliffs) | 4 seamless top tiles + 4 cliff tiles |
| `terrain/` | `terrain_water`, `terrain_lava` | 128 × 80 | 2 × 4-frame seamless animations + cliffs |
| `terrain/` | `props_*.png` × 10 | 4 cells: 32×48 trees, 32×32 rocks and bushes, 64×64 mountains | trees, rocks, mountains, bushes |
| `terrain/` | `fx_fire.png` | 256 × 112 | flames (8 frames, 2 sizes), smoke, embers, scorch marks |
| `units/`, `monsters/`, `heroes/` | 55 characters | 6 × 6 cells of 48² (64² mounted, flying or large; 96² dragon) | idle 4, walk 6, attack 6, hurt 2, death 6, plus a special row (2nd attack, shoot, cast or work) |
| `structures/` | 38 buildings | 4 × 2 cells of 48×64 / 64² / 96² | 4-frame idle animation, plus construction, damaged and ruined |

If a tool can't make a whole sheet in one image, each prompt allows delivering it row by row
(e.g. `unit_human_footman_walk.png`); I assemble the sheets.

## Tips for the image AI

- **Use a tool made for pixel art if you can**, such as a pixel-art model, Aseprite plugins,
  or tools that work at the exact native size. General image models tend to fake pixels or
  smooth them.
- If the output is smooth or blurry, reply: *"Redo it as true pixel art: native NxN px, hard
  edges, only the master palette, no anti-aliasing."*
- If the scale drifts, reply with the numbers: *"The footman must be 26 px tall in a 48 px
  cell, feet on the bottom row."*
- Keep one chat or session per faction, so the model stays in context.
