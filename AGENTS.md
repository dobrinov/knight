# Knight Engine — agent guide

Hex-based isometric 2.5D game engine in Rust (wgpu + winit) for strategy and RPG games, plus a
sandbox app that demonstrates every feature. Targets web (WebGPU with a WebGL2 fallback), desktop,
and mobile. The console backends (PSN, Xbox) need NDA SDKs and are not in this repo.

The previous game prototype ("Knight", Heroes-style TypeScript/Rust game) lives on the
`archive/knight-game` branch. Do not resurrect it on `main`.

## Layout

| Path | What |
| --- | --- |
| `crates/knight-hex` | Pure hex math, no dependencies: axial/cube coords, layouts (pointy/flat), offset & doubled coords, `HexMap`, shapes, A*, movement ranges, flow fields, line of sight / FOV, RNG + value noise. Follows redblobgames.com/grids/hexagons. |
| `crates/knight-core` | Renderer-independent engine: `HexWorld` (tiles, heights, water, materials, fog, chunk meshing, picking), `Camera` + `CameraController`, `Frame` (world drawing + immediate-mode UI), `Scene`/`SceneStack`, `Input`, `Assets` (texture atlas, animations, 8×8 font). Unit-tested without a GPU. |
| `crates/knight-assets` | The bundled pixel-art pack. `Pack` loads and caches it on demand: `material(name)` (terrain), `props`, `fire`, `character(id, team)` (6 animations), `structure(id, team)` (idle + 3 states). `catalog.rs` lists every sheet; it was generated from `docs/art-prompts`. The PNGs are in `assets/`; `tools/` has the JS generators that drew them. Draw pack sprites at `pack.scale(&world)` (the art is 16 px per unit). |
| `crates/knight-net` | Networking, no engine dependency: `Wire` codec, relay protocol (`Rooms`), `Client` over `connect_ws` (tungstenite natively, browser WebSocket on wasm) or `LocalHub` (in-process), `Lockstep` sessions. |
| `apps/relay` | tokio WebSocket relay server with rooms (`cargo run -p knight-relay -- 127.0.0.1:9001`). |
| `crates/knight-engine` | Runtime: winit window/event loop, wgpu renderer (`world.wgsl`, `screen.wgsl`), audio output (`audio_out.rs`: cpal / WebAudio), gamepads (`gamepad_in.rs`: gilrs / Gamepad API), `run(AppConfig, init)`. Re-exports `knight-core` and `knight-hex` (as `hex`), `glam`, `log`, `web_time`, and `knight-net` as `net` behind the default `net` feature. Games depend only on this crate. |
| `apps/sandbox` | Demo app (`publish = false`; it is not part of the engine and no crate depends on it): menu + 17 feature demos (asset pack gallery, battle royale, online play, hybrid timed days, terrain & camera, picking & editing, pathfinding, vision & fog, overlays/light/FX, scenes & UI levels, turn-based single/multi unit, realtime single/multi unit, chat & emotes, routes & transport, stress test). Demos are named after features, not games. Shared logic: `src/tactics.rs` (turn-based units, AI, action director), `src/realtime.rs` (real-time units on hex reservations). Art: `src/art.rs` loads terrain, trees, units and buildings from `knight-assets` (`Pack::with_upscale(2)`, because the rest of the sandbox art is doubled). `assets/` keeps only placeholders the pack doesn't cover yet (resource/spell icons, arrow); the second-batch prompts in `docs/art-prompts` are meant to replace them. `web/index.html` is the web shell. |
| `docs/art-prompts/` | One pixel-art prompt per asset (terrain, props, units, heroes, monsters, structures) for image AIs. Generated by `scripts/art_prompts.py`; edit the script, not the files. Shared rules: 48-colour palette, 16 px per world unit, 1 px `#1B1420` outline, upper-left light, facing right, magenta team colour. |
| `scripts/web.sh` | Build the sandbox for the web (`wasm32` + `wasm-bindgen`) and optionally serve it. |

## Key design decisions

- **Hex navigation only.** Everything that moves uses `HexMover` (`knight-core/src/nav.rs`): it
  accepts only routes of adjacent hexes and always stops on hex centres. Real-time movement adds
  `Reservations` (reserve the next hex before stepping; no overlap). Never add free movement.
- **Terrain sets movement.** `Material::move_cost` feeds `HexWorld::step_cost` (real-time time
  multiplier) and `HexWorld::step_points` (turn-based movement points). Keep both modes on these.
- **Fixed view direction, no rotation.** The camera always looks north (−z) at a configurable
  pitch. Terrain meshing therefore only emits walls facing the viewer. Do not add camera rotation
  back without discussing it.
- **World space:** layout `(x, y)` maps to world `(x, z)`, `y` is up, height level × `height_step`.
- **Rendering:** chunked (16×16 axial) terrain meshes.
  - **Lazy meshing:** `HexWorld::visible_chunks(camera)` meshes only the chunks whose footprint is
    on screen, nearest first.
    - Each call meshes at most `mesh_budget` chunks.
    - Chunks are re-meshed when their tiles or the fog change. `update_fog` costs only the hexes
    that changed (the world tracks the visible set: `visible_hexes`).
    - Beyond `mesh_cache`, the least recently used chunks are evicted. The renderer caps its GPU
      buffers the same way.
  - `visible_chunk_keys(camera)` gives the same chunk list, for culling a game's own objects:
    bin them by `HexWorld::chunk_of`.
  - `prepare()` meshes everything up front (small maps, tests).
  - For minimaps on big maps, use `Minimap`: an atlas image updated in place through
    `Assets::replace`, which uploads only that rectangle. Don't use a second camera there.
  - `cargo run -p knight-core --example bench_terrain --release` measures 128² to 2048² maps.
- **Atlas pages:** the atlas is a texture array of 2048² pages (WebGL2's limit), up to
  `MAX_ATLAS_PAGES`.
  - A region's page is the whole-number part of its U coordinate, so vertices have no page
    field. The shaders split it back out (`atlas_sample`).
  - To read atlas pixels, use `Region { page, x, y }`, not the UVs.
  - `Assets::replace` rewrites an image in place, uploading only that rectangle.
    `Assets::add_animated` builds animated textures (water, lava) on top of it, and the runtime
    advances them each frame.
  - Cliff textures with `Material::side_texture_size` tile at their true world size, instead of
    being stretched over each height level.
- **Depth and layers:** a depth buffer for terrain; billboards carry the clip depth of their feet (`Vertex::depth`) so
  sprites sort like painter's algorithm; transparent pass for water/overlays; an `on_top` layer
  for routes/markers; one texture atlas (2048²) for everything including the font.
- **Render modes:** `PixelArt { scale }` renders the world at 1/scale and upscales with nearest
  filtering (camera pixel-snaps, zoom snaps to pixel-perfect levels); `HiRes { msaa }` renders at
  full resolution with linear filtering + 4× MSAA. UI is always drawn at native resolution.
- **Colours are sRGB end to end**; the screen shader linearises only if the surface is sRGB.
- **Camera zoom is in logical pixels** (`Camera::dpr` converts); UI is laid out in logical pixels.
- **UI input:** buttons return `true` when clicked during `draw`, and also report to next frame's
  `ctx.input.ui_clicked(id)`; use `ctx.input.pointer_over_ui()` to avoid clicking through panels.
- **Hazards:** `zone.rs` (`ShrinkingZone`, `Wildfire`) drive closing-in maps; AI avoids them via
  `tactics::ai_turn_with(safe, refuge, sight)`. Units have a `faction` (free-for-all = one each).
- **Camera:** `CameraController` edge-scrolls by default (12 logical px band, off over UI).
- **Turn modes:** turn-based (`tactics.rs`), real time (`realtime.rs`) and hybrid timed days
  (`DayClock` + `ActionBudget` in `clock.rs`, demo `hybrid.rs`) all share `HexMover` and terrain costs.
- **Audio:** games use `ctx.audio` (`Audio`: add/play/play_at/play_music). Backends drain the
  command queue each frame; `Mixer` (core) does software mixing natively and in tests. Sounds are
  WAV or `synth` (`Sfx` presets, `chiptune`). Browsers need a click before audio starts.
- **Gamepads:** backends report `PadState` into `Input`; `Input::apply_gamepad` maps pad 0 to
  virtual mouse, keys and camera gestures (`gamepad_cursor`, on by default).
- **Networking:** payloads are game-defined `Wire` messages inside relay `Send`/`Data`. Web
  multiplayer needs the relay (browsers can't listen). Use `Lockstep` for deterministic sims.
- **Chat & emotes:** `Speech` (`speech.rs`) owns crowd rules (one bubble per speaker, visible
  budget by priority, markers, no overlap, merged emotes, rate limits, log). Games supply anchors.
- **Scenes:** `update` → `Transition` (Push/Pop/PopWith/Switch/Reset/Quit); results flow down the
  stack with `PopWith(Box<dyn Any>)` + `on_resume`. Non-overlay transitions fade (`Frame::fade`
  appends a full-screen quad to the UI mesh; the renderer knows nothing about fades).
- **Save/load:** `HexWorld::to_bytes` / `load_bytes` (`save.rs`, format `KHEX` v1) carry layout,
  heights, materials by name, water and fog. Games add their materials first; unknown names map
  to material 0. Keep the format self-contained (no `knight-net` dependency in core).
- **Web:** the page's CSS sizes the canvas; the runtime keeps the backing store at CSS size ×
  `devicePixelRatio`. `ctx.status` is mirrored to the canvas `data-status` attribute for tests.

## Commands

Rust comes from rustup (Homebrew's Rust has no wasm target):
`export PATH="/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH"`.

```sh
cargo test --workspace                       # unit tests (hex math, core, headless battle sim)
cargo clippy --workspace --all-targets       # must stay warning-free
cargo fmt --all                              # rustfmt.toml: width 120
cargo run -p knight-sandbox --release        # native sandbox window
scripts/web.sh serve                         # web build + http://localhost:8080
cargo run -p knight-relay --release          # relay for Online Play (ws://localhost:9001)
cargo build -p knight-engine --target wasm32-unknown-unknown   # quick wasm type-check
```

`wasm-bindgen` CLI must match the pinned crate version (`=0.2.129` in `Cargo.toml`).

## Verifying changes

Verify visual/interactive changes in a real browser, not just by compiling:

1. `scripts/web.sh` then serve `apps/sandbox/web` (e.g. `python3 -m http.server 8080 --directory apps/sandbox/web`).
2. Drive it with agent-browser (`open`, `press`, `screenshot`) or Playwright for mouse drags/wheel.
   Read `data-status` on `canvas#knight` to assert state (each demo writes a status line).
3. Multiplayer: run the relay and open two pages; gamepads: stub `navigator.getGamepads` in an
   init script (the backend accepts plain objects); audio: the stats panel shows `snd` once
   unlocked.
4. Check both WebGPU and the WebGL2 fallback (`index.html?backend=webgl2` hides `navigator.gpu`),
   DPR 1 and 2, and a phone-sized viewport.

Keyboard shortcuts in the sandbox: `1`–`9` open demos from the menu, `Esc` goes back, `P` toggles
pixel-art rendering.

## Conventions

- Keep `knight-hex` dependency-free and `knight-core` GPU-free; put GPU/window code in `knight-engine`.
- Match the surrounding style: doc comments on public items, small focused modules, tests next to code.
- New engine features should get a sandbox demonstration.
- Commit only when asked. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
